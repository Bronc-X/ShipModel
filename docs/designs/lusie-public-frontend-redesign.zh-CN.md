# Lusie 公开展示层重设计方案

## 决策

为 `lusie.cn` 建设一套新的 React + Vite 公开展示前端。

现有 PHP/ThinkPHP 业务系统继续保留，用于登录、注册、赛事报名提交、证书、会员、商户/管理后台等业务流程。

第一版发布应把网站从老式活动门户，重新定位为中国模型运动赛事的清晰服务入口。

## 产品目标

新的公开展示前端应该帮助访问者快速回答四个问题：

1. 现在有哪些比赛可以参加？
2. 我该如何报名？
3. 规则、通知、下载资料、成绩和证书在哪里？
4. 出问题时应该联系谁？

这是第一版发布的成功标准。视觉质感重要，但前提是它能让这些任务更容易完成。

## 为什么要升级

当前公开网站已经有足够内容，具备实用价值，但展示层削弱了信任感和转化效率。

- 移动端基本是桌面优先布局，空间拥挤。
- 首页混合了很多模块，但没有强用户路径。
- `Model学院` 被当作核心栏目推广，但多个入口进入后只是升级占位页。
- 新闻、通知、成绩公告和下载资料没有清晰分离。
- 部分板块内容过旧，尤其是早年精彩回顾和社交/外链区域。
- 多个静态页面内容很薄，甚至接近空页。
- 赛事列表和赛事详情可用，但报名与规则发现路径还不够明确。

如果该平台会继续作为模型运动赛事发现和报名的主要官方入口，那么这次升级是值得做的。

## 非目标

- 不重建登录系统。
- 不重建选手注册。
- 不重建会员注册。
- 不重建赛事报名提交。
- 不重建证书生成或下载。
- 不重建商户或机构后台。
- 第一版不建设商城。
- 第一版不建设社区。
- 第一版不建设完整课程平台。

## 首页结构

1. 首屏：当前主赛事、日期、主行动、次行动。
2. 快捷操作：报名、下载规则、阅读指南、查询成绩、获取帮助。
3. 当前赛事：展示正在报名、比赛中和已完赛赛事的状态卡片。
4. 官方通知：高信任度、带日期、带分类的公告。
5. 报名流程：简单的四步指南。
6. 赛事分类：航海、车辆、建筑、红色教育主题。
7. 成绩与证书：入口和近期成绩公告。
8. Model 学院：实用学习和器材指导，不做空承诺。
9. 作品与回顾：当前或常青作品展示，不使用陈旧的 2021/2022 填充内容。
10. 机构入口：学校和俱乐部组织参赛路径。
11. 联系方式和服务时间。

## 数据策略

### 第一版

如果 PHP API 尚未准备好，使用人工整理的 JSON 或小型静态内容层。

这样可以控制范围，让前端发布不被后端改造阻塞。

### 1.5 版

要求 PHP 后端提供只读 JSON 接口：

```text
GET /api/public/banners
GET /api/public/competitions
GET /api/public/competitions/:id
GET /api/public/articles
GET /api/public/articles/:id
GET /api/public/downloads
GET /api/public/faqs
```

### 第二版

只有当人工 JSON 开始拖慢运营时，再迁移到 CMS 或后台管理内容系统。

除非内容团队已经准备好运营 CMS，否则第一版不要引入 CMS。

## 设计方向

网站应当像一个官方赛事服务平台，而不是营销落地页。

- 使用克制的官方配色，以强蓝、白色和一个强调色为主。
- 赛事卡片要有足够信息密度，便于快速扫描。
- 主要行动必须明显：报名、规则、指南、成绩。
- 尽可能使用真实比赛和模型图片。
- 减少粒子背景和视觉噪音。
- 把移动端作为一等布局。
- 不放空板块。如果功能未准备好，先提供有用的轻量版本。

## 页面要求

### 首页

- 首屏必须展示当前主赛事。
- 必须暴露报名、规则、指南、成绩和帮助的快捷入口。
- 必须展示至少三条当前或重要通知。
- 必须展示至少三个赛事卡片。
- 不允许首页卡片链接到空占位页面。

### 赛事中心

- 必须支持按状态、模型分类、组别和关键词筛选。
- 每个赛事必须展示状态、开始/结束时间、分类、组别、规则链接和行动入口。
- 必须区分展示详情页和老系统报名交接。
- 必须在移动端良好可用。

### 赛事详情

- 必须展示标题、分类、组别、主办/承办方、时间、状态、图片、规则、指南、成绩、证书路径和报名交接入口。
- 必须说明哪些行动需要登录。
- 在业务流程重建前，必须链接到老系统的提交/证书流程。

### 新闻与通知

- 必须分离通知、资讯、成绩公告、下载资料和回顾。
- 必须展示日期、分类、来源和附件。
- 尽可能支持老文章 id 映射。

### 下载中心

- 必须按赛事和资料类型分组文档。
- 必须让 PDF 直接可见，不要把资料藏在文章正文里。

### 报名指南

- 必须是步骤化结构。
- 必须包含：账号创建、实名验证、选择赛事、上传作品、审核、成绩、证书。
- 如有 PDF 或视频链接，必须包含。

### 常见问题

- 必须在这些分类下有真实条目：账号、报名、上传、审核、成绩、证书、机构。

### Model 学院轻量版

- 必须先做成实用学习内容：
  - 我应该先参加哪个比赛？
  - 需要什么器材？
  - 好作品长什么样？
  - 作品如何评审？
- 只有在已经提供有用内容之后，才能展示未来在线课程和附近机构为“后续上线”。

## Agentic Coding 估算

| 工作流 | 估算 |
|---|---:|
| 设计系统和布局 | 3-4 个 agent 工作日 |
| 首页 | 3-4 个 agent 工作日 |
| 赛事中心和详情 | 4-6 个 agent 工作日 |
| 新闻、通知、下载 | 3-5 个 agent 工作日 |
| 指南、FAQ、学院、静态页 | 3-5 个 agent 工作日 |
| 老路由兼容、QA、打磨 | 3-5 个 agent 工作日 |

如果按高视觉质量和高交互质量实现，总计：19-29 个 agent 工作日。

日历时间：包含内容审阅和 QA，约 4-6 周。

此前 12-18 天的估算只有在视觉野心中等、内容已经准备好、后端/API 工作极少时才可能成立。

## 成功指标

- 新访问者能在 10 秒内找到当前赛事。
- 新访问者能在 15 秒内找到规则/下载资料。
- 新访问者无需联系客服也能理解报名流程。
- 移动端页面不需要横向滚动。
- 首页没有卡片链接到空占位页面。
- 重要老 URL 不会 404。
- 官方通知和成绩公告有明显区分。
- 支持联系方式和服务时间能从指南和 FAQ 中看到。

## 风险

### 风险 1：内容未准备好

空板块会让新前端显得虚假。

缓解：少做板块，但每个板块都必须有用。

### 风险 2：老链接断裂

搜索引擎、学校和既往通知可能仍在使用老 URL。

缓解：第一版就保留重定向和兼容映射。

### 风险 3：数据来源不清楚

如果前端依赖抓取老页面，维护会很脆弱。

缓解：第一版可以使用人工整理 JSON，但 1.5 版应增加只读 PHP API。

### 风险 4：范围扩张到业务流程

重建报名、会员或证书会成倍增加风险。

缓解：在产品文案和路由设计中明确老系统交接。

### 风险 5：视觉打磨掩盖了薄弱的信息架构

一个漂亮但仍然让规则和报名难找的首页，就是失败。

缓解：把任务完成作为验收标准。
